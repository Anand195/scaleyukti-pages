Key Findings

  1. WACRM has NO public API. AISensy offers two complete API systems: Campaign API (JWT-based) and Project API (password-based) with full REST coverage. This is WACRM's single biggest gap — blocking integrations, partnerships, and enterprise adoption.
  2. AISensy's "Manage" module alone has 11 sub-modules (Template Gallery, Opt-in Management, Live Chat Settings, Campaign Settings, User Attributes, Canned Messages, Agents, Tags, Analytics, Billing, Notifications). WACRM's equivalent Settings has only 4 tabs.
  3. Contact data model is significantly richer in AISensy — 25+ fields including custom attributes ($variables), source tracking, opt-in status, MAU status, WA conversation status, and multiple tag support per contact.
  4. AISensy has an App Store / Integration Marketplace with 18+ native integrations (Shopify, WooCommerce, Zoho, Razorpay, PayU, Google Sheets, Dialogflow, LeadSquared, WebEngage, etc.). WACRM has none.
  5. WACRM lacks AI features entirely. AISensy actively promotes AI Messages, AI Flows, and AI-powered template generation throughout the platform.
  6. AISensy has Facebook/Instagram Ads Manager built-in with ad credits, CTWA setup, and campaign management. WACRM has no advertising capabilities.
  7. AISensy's flow builder supports catalogue management (WhatsApp Commerce), products, and AI routing. WACRM's automations are basic event-trigger workflows.
  8. Developer Hub is a first-class citizen in AISensy — with API key management, webhook config, documentation links all in one place. WACRM has nothing comparable.

Gap Analysis — Detailed Breakdown

Each missing feature analyzed for business impact, technical impact, and implementation complexity.

1. Public REST API — Campaign + Project 10

Why it matters

Without a public API, WACRM cannot integrate with CRMs, ERPs, e-commerce platforms, or any third-party system. This is the primary integration mechanism for enterprise customers. AISensy's API enables automated WhatsApp messaging triggered from any external system — a core requirement for SMBs using multiple tools.

Business Impact

  • Blocks enterprise sales entirely — large customers require API access
  • Prevents no-code integrations (Zapier, Pabbly, Integrately)
  • Limits WACRM to manual-only operations
  • Prevents partnership integrations with CRMs, payment gateways, e-commerce

Technical Impact

  • Requires new API layer (REST + authentication + rate limiting)
  • Needs API key management system in database
  • Requires comprehensive API documentation (OpenAPI/Swagger)
  • Backend: New controllers, middleware, serializers, versioning
  • Database: API keys table, rate limit tracking, audit logs

Implementation Complexity: HIGH

Estimated: 4-6 weeks for MVP (campaign send + contact CRUD + webhook endpoints)

Priority: P0 | Criticality: 10/10

2. API Key Management & Developer Hub 10

Why it matters

AISensy has a dedicated Developer Hub with JWT-based API keys, project API keys, webhook configuration, and documentation links. WACRM has none of this infrastructure.

Key observations from AISensy

  • API Campaign Key uses JWT with claims: id, name, appName, clientId, activePlan, iat
  • Separate Project API Key with X-AiSensy-Project-API-Pwd header auth
  • Copy Key + Regenerate Key actions in UI
  • 4 tabs: API Campaign Key, Project API Keys, Project Webhooks, Documentation

Implementation Complexity: MEDIUM

Estimated: 2-3 weeks for auth system + UI + key management

Priority: P0 | Criticality: 10/10

3. Webhook Management System 9

WACRM has basic webhooks (forward + auto-reply). AISensy has a full webhook management system with getting-started guides, event types, and configuration UI.

Required enhancements

  • Multiple webhook endpoints per project
  • Event type filtering (message.received, message.sent, contact.created, etc.)
  • Webhook retry logic with exponential backoff
  • Webhook logs and delivery status dashboard
  • Webhook secret/signature verification
  • Manual test/replay capability

Priority: P0 | Criticality: 9/10

AISensy supports dynamic custom attributes using $variable naming (e.g., $PreferredLocation, $Projects, $PurchasePurpose, $SiteVisitDate). WACRM only has Name, Phone, Email, Company, Tags.

Security Recommendations for WACRM

  1. Implement JWT-based API authentication with scoped claims (project_id, permissions, expiry)
  2. Add rate limiting middleware — per API key, per IP, configurable by plan tier
  3. Implement RBAC — Owner, Admin, Manager, Agent roles with granular permissions
  4. Add audit logging — track all API calls, key generation, webhook deliveries, admin actions
  5. Webhook signature verification — HMAC-SHA256 signatures so receivers can verify payload authenticity
  6. API key encryption at rest — store hashed keys, never plaintext after generation
  7. CORS configuration — restrict to known origins
  8. Input validation — all API inputs validated against schemas
  9. HTTPS enforcement — reject all non-HTTPS requests
  10. Plan-based access control — feature gating by subscription tier

Database & Schema Recommendations

New Tables Required

1. API Keys

CREATE TABLE api_keys ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE, name VARCHAR(100) NOT NULL, key_hash VARCHAR(255) NOT NULL UNIQUE, key_prefix VARCHAR(8) NOT NULL, -- for display: "sk_live_..." scopes TEXT[] NOT NULL DEFAULT '{}', last_used_at TIMESTAMPTZ, expires_at TIMESTAMPTZ, is_active BOOLEAN DEFAULT true, created_by UUID REFERENCES users(id), created_at TIMESTAMPTZ DEFAULT now(), updated_at TIMESTAMPTZ DEFAULT now() ); CREATE INDEX idx_api_keys_project ON api_keys(project_id);

2. Contact Custom Attributes

CREATE TABLE contact_attribute_defs ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE, name VARCHAR(100) NOT NULL, display_name VARCHAR(200), data_type VARCHAR(20) DEFAULT 'string', UNIQUE(project_id, name) ); CREATE TABLE contact_attribute_values ( contact_id UUID REFERENCES contacts(id) ON DELETE CASCADE, attribute_id UUID REFERENCES contact_attribute_defs(id) ON DELETE CASCADE, value TEXT, updated_at TIMESTAMPTZ DEFAULT now(), PRIMARY KEY(contact_id, attribute_id) );

3. Webhooks

CREATE TABLE webhooks ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE, url TEXT NOT NULL, secret VARCHAR(255), events TEXT[] NOT NULL DEFAULT '{}', is_active BOOLEAN DEFAULT true, created_at TIMESTAMPTZ DEFAULT now() ); CREATE TABLE webhook_deliveries ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), webhook_id UUID REFERENCES webhooks(id) ON DELETE CASCADE, event_type VARCHAR(50), payload JSONB, response_status INTEGER, response_body TEXT, attempt_count INTEGER DEFAULT 1, delivered_at TIMESTAMPTZ, created_at TIMESTAMPTZ DEFAULT now() );

4. RBAC & Agents

CREATE TABLE roles ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE, name VARCHAR(50) NOT NULL, -- owner, admin, manager, agent permissions TEXT[] NOT NULL DEFAULT '{}', UNIQUE(project_id, name) ); CREATE TABLE project_members ( project_id UUID REFERENCES projects(id) ON DELETE CASCADE, user_id UUID REFERENCES users(id) ON DELETE CASCADE, role_id UUID REFERENCES roles(id), joined_at TIMESTAMPTZ DEFAULT now(), PRIMARY KEY(project_id, user_id) );

5. Audit Logs

CREATE TABLE audit_logs ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), project_id UUID REFERENCES projects(id) ON DELETE CASCADE, actor_id UUID REFERENCES users(id), action VARCHAR(100) NOT NULL, resource_type VARCHAR(50), resource_id UUID, details JSONB, ip_address INET, user_agent TEXT, created_at TIMESTAMPTZ DEFAULT now() ); CREATE INDEX idx_audit_project_time ON audit_logs(project_id, created_at DESC);

6. Rate Limiting

CREATE TABLE rate_limits ( key VARCHAR(255) PRIMARY KEY, window_start TIMESTAMPTZ NOT NULL, count INTEGER DEFAULT 1, ttl INTEGER NOT NULL );

UI/UX Assessment

WACRM UI Observations

  • Clean, minimal interface — easy to navigate, 8 sidebar items
  • Sidebar navigation with clear labels, active state indication
  • Dashboard has good analytics cards with trend indicators
  • Pipelines has functional Kanban board with drag-drop

  • AI features promoted in banners across all pages (repetitive)
  • Help links embedded contextually (good pattern)
  • Quick Guide sections on each module page
  • Template Explore gallery with industry filters — excellent UX
  • Developer Hub has clear 4-tab layout with copy-key functionality

UX Recommendations for WACRM

  1. Add contextual help links on each page (like AISensy's "Quick Guide")
  2. Implement onboarding wizard for new users (WABA setup, template creation, first broadcast)
  3. Add video tutorials section (but don't auto-play modals)
  4. Show account health status on dashboard (WABA status, quality rating, quota)
  5. Consolidate Settings as features grow — avoid AISensy's overly deep hierarchy
  6. Keep the clean sidebar — it's actually better than AISensy's crowded layout
  7. Add search across all modules (global search)
  8. Implement dark mode for developer-friendly usage
