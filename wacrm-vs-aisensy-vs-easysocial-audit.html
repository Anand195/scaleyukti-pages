Gap Analysis — Prioritized Breakdown

Each gap analyzed for business impact, technical complexity, and justified with platform evidence.

1. Public REST API 10 | Both competitors have it

Evidence: AISensy has 2 complete API systems (Campaign JWT + Project password). EasySocial has webhook system and n8n integration. WACRM has zero public API endpoints.

Why it matters

Without API, WACRM cannot integrate with any CRM, ERP, e-commerce, or third-party system. This blocks enterprise sales, partnerships, and automation use cases. Every serious WhatsApp CRM platform has an API.

What to build

POST /api/v1/campaigns/send # Send template message GET /api/v1/campaigns # List campaigns GET /api/v1/campaigns/:id # Campaign status POST /api/v1/contacts # Create/upsert contact GET /api/v1/contacts # List/search contacts GET /api/v1/contacts/:id # Contact details PUT /api/v1/contacts/:id # Update contact GET /api/v1/templates # List templates POST /api/v1/webhooks # Register webhook GET /api/v1/webhooks # List webhooks GET /api/v1/analytics/messages # Message stats

Effort: High | TImeline: 4-6 weeks MVP | Priority: P0

2. Integration Marketplace 9 | AISensy: 18+ | EasySocial: 16+

Evidence: Both competitors have rich integration stores. EasySocial has 16 integrations including Google Calendar, Zoho, Stripe, Shopify, WooCommerce, ChatGPT, n8n, Live Translation. AISensy has 18+ via App Store.

Why it matters

Integrations create ecosystem lock-in. Customers pick platforms that connect to their existing tools. Each integration = a reason to stay.

Start with these 5:

  1. Google Sheets (most requested)
  2. n8n/Zapier webhook (widest reach via no-code)
  3. Zoho CRM (Indian SMB favorite)
  4. Payment gateway (Razorpay/Stripe)
  5. Shopify/WooCommerce (e-commerce)

Effort: High | Priority: P1

3. Custom Contact Attributes 9 | Both competitors support

Evidence: AISensy uses $variable naming for custom fields (25+ fields observed: $PreferredLocation, $Projects, $SiteVisitDate, etc.). EasySocial supports custom fields like "check for demo", "Need to Contact Directly", "Time Selection for Consult", "Date Selection for Consult".

WACRM only has: Name, Phone, Email, Company, Tags. Severely limited for real-world CRM use.

Key UX Findings

WACRM — Strengths & Gaps

Strengths: Cleanest interface. Minimal sidebar with 8 items. Consistent layout. Good use of white space. Kanban board for pipelines is functional.

Gaps: No help center/support. No onboarding flow. No WABA health monitoring. No bulk actions. No confirmation dialogs for destructive actions. No mobile app.

AISensy — Strengths & Gaps

Strengths: Feature-rich. Contextual help links on each page. Intercom chat for support. Onboarding resources. Training call scheduling.

Gaps: Extremely cluttered dashboard. Auto-playing video modals (intrusive). Deep hierarchy (Manage has 11 sub-tabs). AI banners on every page (repetitive). Too many prompts on dashboard.

EasySocial — Strengths & Gaps

Strengths: Best usability score (35/40). Natural language UI. Emoji usage feels friendly. Suggested Actions carousel is excellent. Help Centre with WhatsApp chat. 404 pages are helpful (URL copy for support). Mobile apps available.

Gaps: Plan-gating can be frustrating (features visible but locked). Right sidebar can feel busy. Beta features mixed with stable. Some features throw 404 instead of plan-gate.

UX Recommendations for WACRM

  1. Add WABA health status on dashboard — both competitors do this. Users need to see WhatsApp health, messaging tier, payment status at a glance.
  2. Implement Help Centre — EasySocial's WhatsApp-based support chat is brilliant. Add searchable knowledge base + WhatsApp support.
  3. Add onboarding wizard — Guide new users: Connect WABA → Create template → First broadcast → Install widget.
  4. Add bulk actions — Both competitors support bulk contact operations. This is critical for SMB efficiency.
  5. Keep the clean UI — WACRM's minimal design is actually its UX advantage. Don't over-clutter like AISensy.
  6. Add confirmation dialogs — Prevent accidental deletes/sends with simple confirmations.
  7. Mobile responsive — EasySocial has dedicated mobile apps. At minimum, make WACRM mobile-responsive.

10 Security Recommendations for WACRM

  1. JWT-based API authentication — HMAC-SHA256, scoped claims (project_id, permissions, expiry)
  2. Rate limiting middleware — per API key, per IP, tiered by plan
  3. RBAC implementation — Owner > Admin > Manager > Agent roles with granular permissions
  4. Audit logging — track API calls, key generation, webhook deliveries, admin actions
  5. HMAC-SHA256 webhook signatures — receivers can verify payload authenticity
  6. API key hashing at rest — never store plaintext after generation
  7. CORS configuration — restrict to known origins
  8. Input validation — all API inputs validated against schemas
  9. HTTPS enforcement — reject non-HTTPS requests
  10. Plan-based access control — feature gating by subscription tier (both competitors do this)

Database & Schema Recommendations

New Tables Required for Feature Parity

1. API Keys

CREATE TABLE api_keys ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), project_id UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE, name VARCHAR(100) NOT NULL, key_hash VARCHAR(255) NOT NULL UNIQUE, key_prefix VARCHAR(8) NOT NULL, -- "sk_live_..." scopes TEXT[] NOT NULL DEFAULT '{}', last_used_at TIMESTAMPTZ, expires_at TIMESTAMPTZ, is_active BOOLEAN DEFAULT true, created_by UUID REFERENCES users(id), created_at TIMESTAMPTZ DEFAULT now() );

2. Custom Contact Attributes

CREATE TABLE contact_attribute_defs ( id UUID PK, project_id UUID FK, name VARCHAR(100) NOT NULL, -- $prefixed display_name VARCHAR(200), data_type VARCHAR(20) DEFAULT 'string', UNIQUE(project_id, name) ); CREATE TABLE contact_attribute_values ( contact_id UUID FK, attribute_id UUID FK, value TEXT, updated_at TIMESTAMPTZ DEFAULT now(), PRIMARY KEY(contact_id, attribute_id) );

3. Enhanced Webhooks

CREATE TABLE webhooks ( id UUID PK, project_id UUID FK, url TEXT NOT NULL, secret VARCHAR(255), events TEXT[] NOT NULL DEFAULT '{}', -- ["message.received","contact.created"] is_active BOOLEAN DEFAULT true, retry_count INT DEFAULT 3, created_at TIMESTAMPTZ DEFAULT now() ); CREATE TABLE webhook_deliveries ( id UUID PK, webhook_id UUID FK, event_type VARCHAR(50), payload JSONB, response_status INTEGER, attempt_count INTEGER DEFAULT 1, delivered_at TIMESTAMPTZ, created_at TIMESTAMPTZ DEFAULT now() );

4. RBAC

CREATE TABLE roles ( id UUID PK, project_id UUID FK, name VARCHAR(50) NOT NULL, -- owner, admin, manager, agent permissions TEXT[] NOT NULL DEFAULT '{}', UNIQUE(project_id, name) ); CREATE TABLE project_members ( project_id UUID FK, user_id UUID FK, role_id UUID FK, joined_at TIMESTAMPTZ DEFAULT now(), PRIMARY KEY(project_id, user_id) );

5. Segments

CREATE TABLE segments ( id UUID PK, project_id UUID FK, name VARCHAR(100) NOT NULL, rules JSONB NOT NULL, -- [{"field":"tags","op":"contains","value":"lead"}] contact_count INTEGER DEFAULT 0, created_at TIMESTAMPTZ DEFAULT now() );

6. Audit Logs & Rate Limiting

CREATE TABLE audit_logs ( id UUID PK, project_id UUID FK, actor_id UUID FK, action VARCHAR(100), resource_type VARCHAR(50), resource_id UUID, details JSONB, ip_address INET, created_at TIMESTAMPTZ DEFAULT now() ); CREATE TABLE rate_limits ( key VARCHAR(255) PRIMARY KEY, window_start TIMESTAMPTZ NOT NULL, count INTEGER DEFAULT 1, ttl INTEGER NOT NULL );
